# Jovro Backend সেটআপ — Supabase (ফ্রি)

এই ফাইলটা ধাপে ধাপে ফলো করলেই অ্যাপের আসল backend (ডেটাবেস + লগইন) তৈরি হয়ে যাবে। সব ফ্রি, **কোনো কার্ড/টাকা লাগবে না।**

---

## ধাপ ১ — Supabase অ্যাকাউন্ট খোলো

1. ফোন/কম্পিউটারের ব্রাউজারে যাও: **supabase.com**
2. **Start your project** → GitHub বা Google দিয়ে সাইন আপ করো (ফ্রি)।

## ধাপ ২ — নতুন Project বানাও

1. Dashboard-এ **New Project** চাপো।
2. নাম দাও: **Jovro**
3. **Database Password** — একটা শক্ত পাসওয়ার্ড দাও আর সেটা কোথাও লিখে রাখো (পরে লাগবে)।
4. **Region** বেছে নাও: **Singapore (Southeast Asia)** — বাংলাদেশের সবচেয়ে কাছে, অ্যাপ দ্রুত চলবে।
5. Plan: **Free** রেখে **Create new project** চাপো। ১–২ মিনিট অপেক্ষা করো, project তৈরি হয়ে যাবে।

## ধাপ ৩ — ডেটাবেসের টেবিল বানাও (schema.sql)

1. বাম পাশের মেনু থেকে **SQL Editor** খোলো → **New query**।
2. এই repo-র `supabase/schema.sql` ফাইলের **পুরো লেখা কপি** করে পেস্ট করো।
3. **Run** চাপো। "Success" দেখালেই টেবিল, নিয়ম (RLS) — সব তৈরি।

## ধাপ ৪ — শুরুর ডেটা বসাও (seed.sql)

1. আবার SQL Editor-এ **New query**।
2. `supabase/seed.sql` কপি-পেস্ট করে **Run** চাপো — এতে **১১৪টা এলাকা** আর শুরুর সেটিংস বসে যাবে।
3. ⚠️ **নিজেকে Admin বানানো:** প্রথমে অ্যাপে/ Supabase-এ নিজের ইমেইল দিয়ে একবার সাইন আপ করো (তাহলেই তোমার প্রোফাইল তৈরি হবে)। তারপর seed.sql ফাইলের একদম নিচে "MAKE YOURSELF ADMIN" অংশে একটা `--` দিয়ে ঢাকা কোড আছে — সেখানে `YOUR-EMAIL-HERE@example.com`-এর জায়গায় **তোমার নিজের ইমেইল** বসিয়ে, লাইনগুলোর সামনের `--` মুছে, শুধু ওইটুকু Run করো। ব্যাস — ওই অ্যাকাউন্টটাই Admin। (নিয়মটাই এমন: backend-এ যেই ইমেইলের role = admin, সেই অ্যাপে Admin Dashboard দেখবে।)

## ধাপ ৫ — অ্যাপের সাথে কানেক্ট করো (.env)

1. Supabase Dashboard → **Project Settings** (গিয়ার আইকন) → **API**।
2. সেখানে দুটো জিনিস পাবে: **Project URL** আর **anon public key**।
3. অ্যাপের repo-তে `.env.example` ফাইলটা কপি করে নাম দাও **`.env`** — তারপর:
   - `VITE_SUPABASE_URL=` এর পরে Project URL বসাও
   - `VITE_SUPABASE_ANON_KEY=` এর পরে anon key বসাও
4. অ্যাপ আবার build/চালু করলেই অ্যাপ Supabase-এর সাথে কানেক্ট হয়ে যাবে।

> ⚠️ `.env` ফাইলটা GitHub-এ তুলবে না — এটা তোমার নিজের কপি। (anon key পাবলিক হলেও RLS নিয়মই ডেটা পাহারা দেয়, তাই চিন্তা নেই।)

**একটাই ধরা আছে:** ফ্রি project টানা **৭ দিন একদম ব্যবহার না হলে** Supabase সেটা ঘুম পাড়িয়ে (pause) দেয়। ভয়ের কিছু না — Dashboard-এ গিয়ে **এক ক্লিকে Restore** করলেই আবার চালু। আর প্রতিদিন অর্ডার চললে project কখনোই ঘুমাবে না।

সব ধাপ শেষ — এখন থেকে নতুন কাজ হবে: অ্যাপের demo ডেটার বদলে এই ডেটাবেস থেকে ডেটা আনা-নেওয়ার কোড জোড়া দেওয়া।

# Phase 3 — অ্যাপ এখন আসল Backend-এ চলে

উপরের ধাপ ১–৫ শেষ হলে নিচের কাজগুলো করলেই অ্যাপ ডেমো ডেটা ছেড়ে আসল ডেটাবেসে চলা শুরু করবে।

## ধাপ ৬ — Phase 3-এর বাড়তি টেবিল/কলাম (schema_phase3.sql)

1. SQL Editor-এ **New query** খোলো।
2. এই repo-র `supabase/schema_phase3.sql` ফাইলের **পুরো লেখা কপি-পেস্ট** করে **Run** চাপো।
3. ক্রমটা মনে রাখো: **আগে schema.sql → তারপর schema_phase3.sql → তারপর seed.sql**।
4. এই ফাইলে যা আছে: রাইডারের অন-ডিউটি সুইচের কলাম, অর্ডারে রাইডারের আয় (rider earning) রাখার কলাম, অ্যাফিলিয়েট অপেক্ষা-তালিকার (waitlist) নতুন টেবিল, আর লাইভ আপডেটের (realtime) সেটিং। ফাইলটা **দুবার চালালেও কোনো ক্ষতি নেই** (idempotent)।

## ধাপ ৭ — .env মান GitHub Pages-এর build-এ পৌঁছে দেওয়া

অ্যাপটা GitHub Pages-এ চলে — তাই Project URL আর anon key দুটো build-এর সময় অ্যাপে ঢুকতে হবে।

**ভয়ের কিছু নেই:** anon key টা **পাবলিক-সেফ**। ডেটা পাহারা দেয় ডেটাবেসের RLS নিয়ম — key হাতে পেলেও কেউ অন্যের ডেটা দেখতে/বদলাতে পারবে না। (⚠️ শুধু **service_role key** টা সম্পূর্ণ আলাদা জিনিস — ওটা গোপন মাস্টার চাবি, ওটা **কখনোই** অ্যাপে/.env-তে/GitHub-এ বসাবে না।)

**সহজ পথ (তুমি ফোন থেকে কাজ করো বলে এটাই সাজেস্ট করছি):**
1. GitHub-এ repo খোলো → **Add file → Create new file** → ফাইলের নাম দাও: `.env`
2. ভেতরে এই দুই লাইন লিখে বসাও (মান দুটো Supabase Dashboard → Project Settings → API থেকে):
   ```
   VITE_SUPABASE_URL=https://তোমার-project.supabase.co
   VITE_SUPABASE_ANON_KEY=তোমার-anon-key
   ```
3. **Commit** করো। ব্যাস — GitHub Pages-এর পরের build নিজে থেকেই `.env` পড়ে অ্যাপে মান দুটো ঢুকিয়ে দেবে।

> ধাপ ৫-এ ".env GitHub-এ তুলবে না" লেখা ছিল — ওই সতর্কতাটা এখন **শুধু এই দুটো পাবলিক মানের জন্য বদলে গেল**। service_role key-এর জন্য সতর্কতা আগের মতোই আছে।
>
> বিকল্প পথ: `.env` কমিট করতে না চাইলে `src/lib/supabase.ts` ফাইলের একদম উপরে `FALLBACK_SUPABASE_URL` আর `FALLBACK_SUPABASE_ANON_KEY`-এর ফাঁকা জায়গায় একই দুটো মান বসালেও চলবে।

## ধাপ ৮ — নিজেকে Admin বানানো (আবার মনে করিয়ে দিলাম)

1. অ্যাপে **নতুন অ্যাকাউন্ট খোলো (Sign up)** — ইমেইল: **bakervai.bdl@gmail.com**, নাম: **Baker**। (সাইন আপ করলেই তোমার প্রোফাইল তৈরি হয়ে যাবে, role হবে 'customer'।)
2. Supabase-এ ফিরে **SQL Editor** খোলো। `seed.sql` ফাইলের একদম নিচে **"MAKE YOURSELF ADMIN"** অংশে UPDATE লাইনটা **তোমার ইমেইল দিয়েই আগ থেকে ভরা আছে** — শুধু ওই ৩ লাইনের সামনের `--` চিহ্ন মুছে দিয়ে Run করো।
3. ব্যাস — এখন ওই ইমেইল দিয়ে লগইন করলেই Admin Dashboard খুলবে।

মনে রাখো: আসল ক্ষমতাটা থাকে **profiles টেবিলের role**-এ — ইমেইলটা শুধু প্রথমবার সেটআপের পথ।

## ধাপ ৯ — প্রথম রাইডার ও স্টাফ অ্যাকাউন্ট

কারো নিজের আলাদা করে অ্যাকাউন্ট বানিয়ে দেওয়া লাগে না — **সে নিজে সাইন আপ করবে, তুমি শুধু অনুমোদন/ভূমিকা দেবে:**

- **রাইডার:** সে অ্যাপে নিজের ইমেইল দিয়ে সাইন আপ করবে → তারপর অ্যাপের **"রাইডার আবেদন"** ফর্মটা পাঠাবে → তুমি Admin প্যানেল → **রাইডার ব্যবস্থাপনা**-তে গিয়ে **অনুমোদন** চাপলেই কাজ শেষ: তার role নিজে থেকেই rider হয়ে যাবে আর রাইডার সেকশন খুলে যাবে। (অনুমোদনের আগে সে শুধু customer হিসেবেই থাকবে।)
- **সরাসরি রাইডার যোগ** (Admin প্যানেলে ইমেইল লিখে): ওই ইমেইলে **আগে সাইন আপ করা অ্যাকাউন্ট থাকতে হবে** — না থাকলে যোগ করা যাবে না, আগে তাকে সাইন আপ করতে বলো।
- **স্টাফ:** সে সাইন আপ করার পর তুমি Admin → **টিম**-এ তার ইমেইল দিয়ে যোগ করে অনুমতি (permission) টিক দিলেই সে staff হয়ে যাবে।

## ধাপ ১০ — শুরুর ক্যাটালগ বসানো (সিড ডেটা)

এলাকার তালিকা (১১৪টা) seed.sql থেকেই বসে যায়। পণ্য/রেস্টুরেন্ট/প্রোমোর জন্য:

1. Admin ইমেইল দিয়ে অ্যাপে **লগইন** করো।
2. **অ্যাডমিন সেটিংস**-এ যাও → একদম নিচে **"ব্যাকএন্ড ডেটা"** কার্ডে **"সিড ডেটা বসান"** বাটন চাপো।
3. তৈরি ক্যাটালগটা ডেটাবেসে বসে যাবে। বাটনটা শুধু **খালি টেবিলেই** ডেটা বসায় — তাই দুবার চাপলেও কোনো ক্ষতি নেই।

## শেষ কথা

- `.env` না থাকলে অ্যাপ **আগের মতোই ডেমো মোডে** চলবে — তাই মাঝপথে থামলেও অ্যাপ ভাঙবে না।
- লাইভ হলে যা যা চলবে: আসল সাইন আপ/লগইন (ইমেইল + পাসওয়ার্ড), সব ডেটা ডেটাবেসে সেভ, অর্ডার দিলে অ্যাডমিন/রাইডারের অ্যাপে **লাইভ আপডেট**, অনুমোদনের ফ্লো — সবই।
